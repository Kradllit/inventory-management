Factory Inventory Management

A two-tier demo app for a parts maker, Catalyst Components: a Vue 3 single-page app reads a FastAPI service that filters JSON files held in memory. No database, no sign-in, no writes that persist.

System architecture

Three layers, two processes. The browser talks to the API directly over HTTP; there is no proxy between them.

Data flow: changing a filter

What happens when someone picks “Tokyo” in the filter bar on the Dashboard.

Filter bar

FilterBar.vue writes selectedLocation in the shared useFilters state.

View reacts

Dashboard.vue watches the filters and calls getCurrentFilters().

api.js

Drops “all” values, builds query params, fires four GETs in parallel.

FastAPI

apply_filters then filter_by_month narrow the in-memory lists.

Aggregate

Summary totals, low-stock count and pending orders are computed and checked by Pydantic.

Render

Results land in refs; computed properties feed KPI cards, SVG charts and tables.

Gaps found while reading

Places where the code disagrees with itself. Some are probably the bugs planted for the workshop.

  • Backlog page has no route. views/Backlog.vue exists, but main.js and the top nav never register /backlog.
  • Client calls endpoints the server lacks. api.js has tasks and purchase-order calls; main.py defines neither (checked: 404).
  • Reports bypasses the API client. It hardcodes http://localhost:8001 and ignores the shared filters.
  • Dates are 2025 only. Quarters are a hardcoded map for 2025; any other year drops out of reports and filters.
  • Backlog count ignores filters. The dashboard summary filters orders and stock but always returns the full backlog count.
  • Wide open by design. CORS allows every origin and uvicorn binds 0.0.0.0: fine for a demo, not for anything real.
